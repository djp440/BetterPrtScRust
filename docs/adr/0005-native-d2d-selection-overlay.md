# 选区遮罩用原生 Win32 + Direct2D 绘制

取代 ADR 0003 中“选区遮罩用 egui”的部分。#2 的原型实测（数据见 ADR 0003）显示，egui（winit + wgpu）的选区遮罩能满足 150 ms 的延迟要求，但前提是 wgpu 设备和遮罩窗口常驻，这时常驻实例的私有工作集约 94 MB，远超 30 MB 的硬约束；如果不常驻，首次触发要 0.5 s 以上，而且用过一次后内存同样降不下来。原生方案在常驻预热时延迟约为 egui 的一半（后续触发中位数 22 ms，egui 为 40 ms），私有工作集约 15 MB。因此选区遮罩改为原生绘制：启动时就建好一个铺满虚拟桌面的 Win32 窗口，隐藏并 cloak 起来，用 D3D11 + Direct2D 渲染；冻结帧由 Desktop Duplication 拍下后直接在 GPU 上交给 Direct2D，不经过 CPU。

## Consequences

- 选区遮罩的代码只存在于 `platform-windows`，移植 macOS / Linux 时要各写一份原生遮罩；`core` 只接触区域和冻结帧，不受影响。
- 标注就在这个遮罩窗口上进行。标注图层和标注工具条最好也用 Direct2D 画在同一个窗口里，否则一打开工具条就要加载 wgpu，内存或延迟的问题会再次出现。具体做法由标注 ticket 决定。
- 设置、OCR 结果面板等其余界面仍按 ADR 0003 使用 egui。但实测一旦加载 wgpu，私有工作集会增加 60–90 MB，关闭后也不会完全回落。这些界面要么放进按需启动、用完就退出的子进程，要么在各自的 ticket 里重新评估。
- “常驻内存 < 30 MB”这里按任务管理器“内存”列（私有工作集）计算。如果按工作集计算，原生遮罩常驻预热时也有 51–59 MB，其中大部分是 D3D11 和显卡驱动 DLL 的共享页。

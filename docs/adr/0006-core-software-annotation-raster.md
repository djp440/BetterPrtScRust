# 标注在 core 里用软件光栅化，遮罩只显示合成好的画布

标注（框、箭头，以后的马赛克和文字）由 `core` 在截图的像素坐标里用 CPU 光栅化：`AnnotationDocument` 把标注列表叠到区域的冻结帧上，得到最终截图。选区遮罩不自己画标注，只显示 `core` 合成好的一块 RGBA 位图（遮罩的“画布”，`SelectionOverlay::show_canvas` / `update_canvas`）：区域锁定时整块上传一次，之后每次改动只重新合成、上传受影响标注的覆盖范围。标注工具条仍是 `OverlayScene` 里的普通项目，由 Direct2D 画（ADR 0005）。

考虑过让遮罩用 Direct2D 的矢量图元直接画标注、导出时再离屏渲染一遍：画得更快，但屏幕上的标注和最终截图出自两套光栅化，抗锯齿、线宽取整会不一致；合成结果也只能在真机上验证，假平台测不到。软件光栅化让“看到的就是得到的”成为同一份像素，合成逻辑能在 `core` 里直接测试，也不需要加载 wgpu 或额外的 GPU 资源，不影响常驻内存。

## Consequences

- 中文文字标注（#13）：`core` 不内置字体（体积约束），字形由平台能力提供（Windows 上用 DirectWrite 把文字栅格化成覆盖率蒙版），`core` 把蒙版当作一种图元按颜色叠加。文字标注要保存栅格化好的蒙版，保证重绘与最终截图一致，也不随系统字体变化。
- 马赛克（#13）直接读取它下面已合成的像素做块平均，最终截图里无法还原原始内容。
- 每次拖动只重新合成改动标注的覆盖范围；画布大小等于区域大小，单边受 Direct2D 位图上限（16384）限制。长截屏（#22）的结果超过屏幕时，画布需要按视图缩放或分块显示。
- 移植到 macOS / Linux 时，平台只需实现“显示一块位图并按矩形更新”和文字栅格化，标注逻辑不用重写。
